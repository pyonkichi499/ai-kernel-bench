# AI 能力検証の記録

このディレクトリには、AI がカーネルをどこまで自力で書けたかを後から評価するための記録を残します。
記録するのは AI 自身で、PR ごとに追記し、マイルストーンの完了時にまとめます。オーナーの作業は増えません。

## 検証の条件

- 設計、実装、PR の作成、マージまで AI が行う
- 参照してよいもの：学習済みの知識、仕様書（Intel SDM、UEFI、Limine プロトコル、ELF、man ページなど）、
  OSDev Wiki などの解説記事
- 参照しないもの：既存 OS（Linux、xv6 など）のソースコード
- 同じ問題で 3 セッション解決できなければ、オーナーに相談してよい。技術的なヒントは「人間の介入」として記録する。
  方針の確認（「この判断で進めてよいか」）は介入に数えない
- モデルを切り替えるのはマイルストーンの区切りのみ

## ファイルの置き方

- 1 マイルストーン 1 ファイル：`docs/ai-log/<言語>-m<番号>.md`（例：`c-m0.md`、`rust-m3.md`）
- 書式は [TEMPLATE.md](TEMPLATE.md) に従う。言語間やモデル間で同じマイルストーンを比べられるよう、
  見出しと表の列は変えない

## 記録する項目

| 項目 | 内容 |
| --- | --- |
| モデル | 使ったモデルとバージョン。サブエージェントやワークフローで使ったモデルも含む |
| 作業量 | セッション数、おおよその時間、PR 数、コード行数 |
| テストの失敗 | CI が失敗した回数、修正にかかったやりとりの回数 |
| バグ | AI が作り込んだバグの内容、どのテスト層で見つかったか、すり抜けて後のマイルストーンで見つかったか |
| 行き詰まり | 解決に複数セッションかかった問題、自力で解決できなかった問題 |
| 人間の介入 | オーナーから受けた技術的なヒントとその影響。方針の確認は含めない |
| 参照した資料 | 仕様書や解説記事の名前と URL |

後のマイルストーンで見つかったバグは、そのバグを作り込んだマイルストーンのファイルにも
「すり抜けたバグ」として追記します。
