### 進め方

M0 と同じく「インターフェース（ヘッダ）を統合担当が先に書く → 担当ファイルを分けて並列実装 → 観点別の並列レビュー（各自が担当範囲を直接修正）」で進めた。

1. 統合担当が cpu.h / interrupt.h / apic.h / spinlock.h / acpi.h / mmio.h / timer.h / stacktrace.h を書いた。
2. 実装 3 並列：A（GDT/TSS/IDT・例外・スタックトレース）、B（ACPI・APIC・PIT・タイマー・MMIO）、C（スピンロック・printk/panic の排他・kmain）。
3. レビュー 4 並列（CPU/割り込み、ACPI/APIC、ロック/panic、テスト基盤/CI）と解説書を同時に実行。

## 振り返り

- 割り込みが入ったことで「ロックを持ったまま例外が起きる」「報告中に割り込まれる」といった再入の問題が出た。実装担当はそれぞれ自分の部品だけを見ているので気づけず、観点別レビューで初めて見つかった。並列実装では、部品をまたぐ相互作用を専門に見るレビュー観点を必ず置く。
- 並列エージェントが同じ出力先でビルドして互いの生成物を壊した。M2 以降は出力先のロック（R4 の対策）に加え、エージェントごとに別の `OUT` を使うよう指示する。
- 次の M2 への申し送り：mmio_map は Limine のページテーブルに書き足す暫定実装なので、自前のページテーブル（vmm）に置き換える。物理 0 番地の除外、Limine のスタック（bootloader reclaimable）からの切り替えも M2 で行う。
